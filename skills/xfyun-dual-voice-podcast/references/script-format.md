# 双角色脚本格式

参考 [可运行示例](../examples/podcast.json)。JSON 使用 UTF-8。

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 1 |
| `title` | 节目名称 |
| `speakers` | 恰好两个角色，键为英文字母、数字、下划线或短横线 |
| `speakers.<role>.name` | 展示名，不发送给 TTS |
| `speakers.<role>.voice` | 账号已授权的讯飞 vcn，两个角色必须不同 |
| `speed` / `volume` / `pitch` | 各为 0～100，默认 50 |
| `reg` | 英文读法 0～2，默认 0 |
| `rdn` | 数字读法 0～3，默认 0 |
| `settings.pause_ms` | 默认轮次间停顿，0～10000 毫秒，默认 250 |
| `turns` | 按播放顺序排列的非空数组，两位角色均需出场 |
| `turns[].id` | 可选，唯一安全标识符，省略时按顺序生成 |
| `turns[].speaker` | speakers 中的角色键 |
| `turns[].text` | 必填纯文本。不含角色提示、Markdown、HTML、Emoji、Tab 或隐藏控制符 |
| `turns[].pause_after_ms` | 可选，覆盖该轮停顿，末轮默认 0 |
| `turns[].audio_path` | 仅离线 assemble 使用的实际音频文件路径 |

长文本会被拆为低于 12,000 UTF-8 字节的请求，低于官方 64K 字节限制。拆分保持每个字符，可能影响跨句韵律。请求计划里的 `characters` 计入标点、空格与换行，只表示输入字符数量。

两个音色的速度参数相同，不保证实际语速一致。试听后按每位角色分别调整。不要通过增加超长静音来掩盖语音生成的故障。

字幕时间来自合成段 WAV 的真实帧数，停顿计入下一段起点。每个请求对应一个字幕条目，未进行字词级对齐。需要更短的字幕时，优先将脚本拆成更短的轮次，或在后期使用独立的强制对齐流程。

`plan` 不提交请求。`render` 会逐段请求付费 API。成功段以文本和音色参数的哈希保存，同一输出目录下 `--resume` 可复用。修改停顿只需重组，语音内容与声音参数相同的段仍复用音频。
